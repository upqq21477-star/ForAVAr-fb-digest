# foravar-fb-digest 建設藍圖

**交付目標**　使用者首次開啟共用網址，透過手機網頁或對話設計自己的刊物，帶走一份個人專案指示；日後在自己的 AI 專案開新對話，輸入「今天的日報」，即可依已選來源與目的取得報告。支援 Agent Skills 的工具另可安裝個人 Skill。

**文件狀態**　設計基線。下列功能、案例與通過條件供後續施工使用。平台文件只能證明平台提供某項能力；特定帳號、社團、模型能否完成任務，須取得對應實測結果。後續在本文件原位修訂，README 只留入口與目前可用方式。

## 一、共用與個人的界線

| 位置 | 保存內容 | 誰使用 |
|---|---|---|
| 公開 GitHub 與設定頁 | 共用方法、空白設定、連線教學、網頁與輸出範本。示例需標示，可略過 | 建設者維護一次，所有人共用 |
| 使用者手機 | 自己的刊物、來源名單與設定草稿。可修改、匯出、匯入、刪除個人副本 | 本人。重新開頁可還原；跨裝置靠匯出與匯入 |
| 使用者的 AI 專案或本機 Skill | 已確認的目的、選定來源、日常執行流程、輸出格式及失敗處理 | 專案內新對話或已安裝的代理 |
| 使用者授權的服務 | 連線權限；若要持續追新，另需可跨次讀寫的私人進度位置 | 實際執行日報的環境 |

公開模板預設空名單。授權憑證、私人通知連結、社團名單、閱讀紀錄與報告留在使用者選擇的私人位置。網頁若更新，已匯出指示的內容維持可追溯；使用者可匯入自己的設定、預覽差異，再覆用新版。帳號授權由各平台處理。

## 二、使用者的三條路徑

1. **手機網頁設定。** 打開共用網址 → 瞭解用途和限制 → 試用或建立刊物 → 選來源與連線方法 → 預覽、修正 → 複製個人專案指示 → 存入自己的專案 → 開新對話試跑。預覽可用明示的範例，實讀結果另行呈現。
2. **純對話設定。** 使用者提供網址及「設計我的日報」。AI 取得同一套設定問題，以選項或短答完成同樣流程，一次詢問會改變結果的項目。無法讀網址時，提示貼上共用流程文字。有來源的使用者可直接貼網址或資料；輸出須和網頁保留同樣的選擇。
3. **桌面個人 Skill。** 同一份已確認設定可產生資料夾 `foravar-fb-digest/SKILL.md`，含規格要求的名稱、用途說明及可獨立執行的內容。依支援工具顯示安裝位置與一次試用方式。一般對話直接使用文字版。持久指示、安裝方式與可用連接器依產品分別驗證。

共用入口預設啟動設定。已完成設定的個人專案預設開始出報；只有當使用者要求修改，或缺少影響本次執行的設定，才回到相關步驟。只有一份對應刊物就直接執行，多份且無法判定時列出名稱供選擇。

## 三、首次設定頁與對話互動

| 步驟 | 操作 | 產出與通過條件 |
|---|---|---|
| 1．進入 | 顯示用途、資料從哪裡來、能帶走什麼。可試用、開始設定或匯入既有設定 | 試用不必綁帳號。匯入先預覽摘要，再決定套用 |
| 2．定義刊物 | 新增日報或週報，填刊名及「這份報告要幫我判斷什麼」。可建立多刊，選時區；週報選週期界線 | 每刊有獨立識別碼；編輯甲刊不覆寫乙刊 |
| 3．選資料管道 | 勾選 Facebook 社團／追蹤來源、Gmail 通知、YouTube 頻道／訂閱、影片文字或畫面。顯示本次需要的工具、權限、費用條件與替代做法 | 只顯示所選項目的教學。已在當前環境確認可用的步驟可跳過 |
| 4．加入並勾選來源 | 提供貼網址、列出可取得的訂閱或匯入名單。先檢視名稱與來源，再逐項勾選；可補選主題與指定單篇 | 來源清單獨立於刊物，用穩定 ID 關聯。一個來源可供多刊使用 |
| 5．確認讀得到什麼 | 針對候選來源試讀一筆。畫面分別顯示連線、名單／通知、正文／影片文字，以及留言或畫面各層的結果。可改用分享文字、截圖或逐字稿 | 每一層顯示已讀、部分、讀取失敗或未測，以及最短的下一步。靜態頁無權查詢時顯示「到執行環境測試」 |

| 8．新對話試跑 | 在使用者的專案保存指示，開新對話輸入「今天的日報」 | 沿用原選擇，讀取可用來源，顯示結果與缺口；免重貼共用網址 |

每張連線教學卡應回答五件事：在哪個平台操作、要開哪一項功能、會授予什麼權限、如何試讀確認、失敗後可選什麼。平台差異放在教學卡；專案指示只引用當前環境確實可用的能力。在手機開著 ChatGPT 的 Gmail 連線，不等同於設定頁已取得同一權限。

### 手機互動樣稿與正式畫面

[手機設定頁互動樣稿](../prototype/index.html) 為獨立 HTML，下載後以瀏覽器開啟。現階段可填刊名、目的及刊期，批次加入社團名稱、核對截圖、勾選候選名單，查看連線教學、修改並複製本次的私人指示。網址只在本機解析，未檢測遠端網站。本稿用來驗收操作方式；多刊持久保存、完整來源清單、帳號試讀、報告實際版面與 Skill 匯出依原批次施工。

正式頁在刊物清單提供「新增、編輯、預覽、匯出」；在來源頁逐筆顯示來源名稱、可公開的主機名、讀取層次與處置理由。預覽時可切換刊物，點一則展開依據、返回修正。外部內容只呈現經處理的純文字。危險、私密、未知或付費項目顯示「略過並繼續」，不提供直達按鈕。支付鎖固定於本 Skill 範圍內，沒有解除開關。

### 首次設定、社團截圖與空信箱

使用者可在私人看圖對話提供社團截圖，或直接貼出名稱清單。將可辨識名稱列成候選、合併重複、保留相似名稱供本人確認；不推測缺字、社團 ID、網址或成員權限。網頁提供裝置內圖片對照、可複製的辨識題詞與逐行輸入，候選預設不勾選。未有郵件、剛加入或沒開過通知均可完成建刊；以「待試讀」保留來源，後續由本人授權的來源驗證。公開版不附私人截圖或名單。

新手教學涵蓋 Facebook「通知 → 社團」的電子郵件、簡訊，以及個別社團的應用程式內部／推播選項。名稱、版面依版本而異。由本人決定調整，Skill 只說明。通知開啟、通知送達、正文可讀分別記錄。既有社團名單與訂閱可唯讀整理；本 Skill 禁止替人加入新訂閱或啟用任何免費方案，不接受免費期或免綁卡作為例外。

## 四、來源能力與證據

| 管道 | 最小實測 | 可以採用的證據與限制 |
|---|---|---|
| Facebook 網址 | 先測一則貼文，再測從社團入口能否找到另一則有發表時間的貼文 | 單篇成功只證明該篇。分別記錄正文、留言、子回覆與媒體是否可見；只有熱門留言、截斷或上限不明都要標示 |
| Gmail 中的 Facebook 通知 | 在使用者授權的信箱找到一封指定來源的通知 → 取得連結 → 再測貼文正文 | 通知可作發現入口。信件摘錄只當作信件摘錄；私人連結留在個人環境。實測需區分找不到信、連結失效與正文無權限 |
| Facebook 個人匯出或手動分享 | 使用者在裝置選檔，預覽可辨識欄位；或分享貼文文字、截圖 | 名單只用來建立候選來源；有正文才可分析正文。手動材料註明來源、日期或其缺漏，跨日涵蓋範圍由提供材料決定 |
| YouTube 頻道與訂閱 | 公開頻道可貼網址；若要列「我的訂閱」，測本人唯讀授權、分頁及勾選後能否還原 | 能列頻道只證明名單可用。取得影片清單、字幕／逐字稿、觀看畫面分開記錄 |
| 影片字幕與畫面 | 以一支可核對影片測是否有文字或片段，再對照時間點 | 標題、簡介、逐字稿、實際畫面分開。只讀字幕就引用字幕；若開畫面分析，另顯示服務／費用並由本人選擇。僅在零額外費用與權限可確認時選用 Gemini |

**尚待實測**　各環境能讀的篇數、最早與最新發表時間、排序是否完整、私人社團正文與巢狀回覆、通知是否漏發、訂閱是否能列全、字幕或畫面覆蓋範圍。記下工具、日期、樣本、篇數、可見起訖與停止原因。觀察到的篇數不等於平台上限。出現登入、權限或流量限制即停止該路，保留其他來源；不承諾特定頻率可避免帳號限制。

## 五、個人指示與資料怎麼交接

下表是施工需保留的資訊，實作可沿用原設定稿的欄位。供應商工具名稱與憑證不寫死在共用流程。

| 資料 | 最少要有什麼 | 用途 |
|---|---|---|
| 來源 | 穩定 ID、平台、名稱、可供當前環境使用的入口、取得方式 | 區分「已加入名單」與「可讀」；通知追蹤網址不作公開或永久識別碼 |
| 刊物 | ID、名稱、目的、日／週、時區、來源 ID、優先主題、手選單篇、呈現偏好 | 從同一來源產生不同目的的報告；排程時間、星期與交付處只在選用時要求 |
| 讀取結果 | 來源／項目 ID、發表時間、取得時間、證據種類、可見層次、限制與定位資訊 | 區分消息發表和 AI 讀取的時間；可追到原貼文或影片時間點 |
| 跨次進度 | 來源上次完整讀取界線、已見項目或變更、各刊已報項目；記錄存放處 | 同一來源可共用查證；甲刊先出報不會讓乙刊漏報。只在確實寫入後宣稱已保存 |

**匯出個人指示的固定內容**　①觸發語與刊物選擇；②本人目的、時區與時間範圍；③含名稱及可用入口的來源白名單；④選取、分析及排序規則；⑤證據與讀取失敗的處理；⑥報告版面；⑦是否有可讀寫的私人進度、沒有時怎麼出報。只填內部來源 ID 會使另一個模型無法找到資料，匯出時須展開來源。文字超過平台可保存長度時，輸出短指示加私有來源檔，並實測新對話能讀回該檔。

**建議預設**　每份刊物可單獨匯出，也可將選定的多刊匯入同一個專案。設定與日常報告分開保存，日常呼叫不需重新開啟設定頁。若只有可讀的專案指示、缺少跨次可寫位置，可照時區與本刊日期範圍出當期報告，明示「未跨次去重」。有可持久寫入的私人位置，才啟用增量追新。排程與交付服務是另外啟用的能力，使用者輸入一句話即可出報的路徑優先。

## 六、每日／每週的實際執行流程

1. **定位刊物與期間。** 讀已保存設定，辨識要哪份日報／週報。使用者指定期間優先；另有可驗證進度時從上次完整讀取處續接。列出本期範圍與時區；來源資料不足以回溯整段就記涵蓋缺口。
2. **發現新增項目。** 僅讀該刊勾選的來源。來源內按發表時間追新，保留可讀起訖、篇數與停止原因；畫面可切換發表時間排序。通知發送時間與正文發表時間分開。
3. **判讀證據。** 正文、留言、子回覆視為一串。簡短提問也要檢視可讀回覆；有步驟、反例、代價或有根據的分歧，就重新評估深讀價值。影片標記本次取得的是標題、簡介、逐字稿或畫面。
4. **選材與排序。** 先列手選單篇，再列優先主題，再評估其他符合目的者。各組按對刊物目的的重要性與實際影響排序，可用發表時間處理同等項目。已勾來源內的其他有用內容可一句略述，純閒聊略過，含條件或結果的心得保留。來源未勾選就跳過。手選內容即使只有標題仍留位置並標示證據不足。
5. **形成詳報。** 先說發生什麼、對讀者有何用。涉及工具，再按需要解釋輸入、作法、輸出、依賴、限制與可試用步驟；需要比較時查原始文件及類似產品。標示作者說法、已查證、實測、推論與未知。相同證據可供多刊重用；是否值得收錄由各刊目的決定。
6. **交付與續接。** 手機首屏放刊名、日期及主要結論，下方依序為精選、其他動態、來源狀態。每則附依據，術語首次出現附白話解釋；展開才看原理、比較或時間點。投影片式摘要沿用同一份分析，每頁一個結論。完整讀取且範圍可界定才可回報「查無新增」；部分／失敗保留舊的完整界線。已報項目遇新增證據才報變化，重跑同一期能辨識已交付內容；無持久狀態則依前節標示。

## 七、施工先後與停止條件

以下為建議順序。每批交付一個使用者能驗收的結果，功能通過後才在入口標示可用。

| 批次 | 交付物 | 驗收／停止條件 |
|---|---|---|
| A．先證明一條可用路徑 | 一份最小個人指示；一個真實且獲允許的來源樣本，先試直接讀取，再視情況測通知連結或手動提供 | 手機新對話一句話能產出有依據的報告；分列自動讀取與手動提供結果。只通過手動材料，就只宣稱手動路徑成立 |
| B．做出設定器 | 同一份設定欄位與規則供網頁及對話使用；手機完成多刊建立、勾選、試讀狀態、預覽、修改、存取個人副本 | 同一套選擇走兩入口所得刊物、來源、排序、失敗處理一致。重開可還原，修改一刊不影響另一刊 |
| C．接通個人專案及 Skill | 公開入口、一次性教學、可複製的個人專案指示、可安裝 Skill 匯出 | 用實際聊天產品開新對話；另用一個支援 Skills 的桌面工具載入。記產品與實測結果；尚未測的模型保留「未驗證」 |
| D．逐項擴充來源 | 按選擇加上必要的連線檢查、唯讀授權教學、名單匯入、正文／留言／字幕等渠道 | 每個管道至少覆蓋可用與不可用結果。只有成功列名單的管道，介面不標示可讀正文 |
| E．連續出報與選配 | 私人增量進度、跨刊共用證據；需要時才接排程、交付服務與影片畫面分析 | 連續兩次執行加一次重跑，確認不漏刊、無重報、失敗可補讀；排程需額外實測關頁後送達才顯示啟用 |

## 八、端到端驗收案例

| 案例 | 預期結果 |
|---|---|
| 同一消息，甲刊關注 AI 新知，乙刊關注工作流程改善 | 甲刊可介紹更新；乙刊需指出能改善的實際步驟才升級詳報。調整甲刊不改變乙刊 |
| 收到社團通知，但貼文打不開 | 可列通知線索並記正文未取得。不能寫成已分析全文或今日零新增 |
| 主文只有提問，留言有可重做的方法，子回覆指出代價 | 報告保留方法、適用條件與反例；若只讀得到主文，顯示缺少留言 |
| 同一影片只有簡介，手動指定要看 | 保留在優先區，列出可確認的資訊；不推定影片示範步驟或畫面 |
| 兩刊共用來源；第二次讀取中斷 | 已成功的刊物可交付。中斷來源的進度保留，恢復後補讀；另一刊仍取得符合自己目的的項目 |
| 關閉設定頁，換新對話，只打「今天的日報」 | 無須重貼 GitHub 網址、來源與目標，可提出有來源的結果或逐來源說明取不到哪一層 |
| 同一個人設定交給另一個模型或 Skill | 須能辨識同一目的、來源與選材規則。工具受限時明示差異；測過的平台逐一列名，措辭無須相同 |

**下一批施工題詞**

> 執行本藍圖批次 A。使用同一份最小個人專案指示，在一個具名的手機聊天環境，以一個本人可用的真實來源，測「新對話 → 今天的日報 → 有依據的成品」。記下輸入、實際讀到的內容層次、產出與第一個斷點。採手動觸發、零付費 API 及本藍圖的連結與支付邊界。直接讀取失敗可另測使用者提供內容，兩種結果分列。完成一次可核對的出報，或確認第一個無法取得的必要輸入後停止。此批不啟用排程。
